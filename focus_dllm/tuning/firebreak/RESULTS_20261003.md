# FIREBREAK implementation audit — 2026-10-03

This is a mechanism/cost diagnostic, not online generation, task accuracy or an
end-to-end acceleration result. Six previously used development prompts,
HumanEval/MBPP/MATH two each, provided12 same-state verification windows.
No LLaDA/v1 generation or main-table result was rerun or changed.

## A real implementation confound was found and corrected

The first implementation did not recompute the known legal tracked context in
verification. Some tracked tokens had just been accepted from the normal
proposal, but their pre-proposal KV still encoded the earlier MASK input.
Flash recomputes these tracked rows. Therefore the initial12/12/8/1 shadow
counts were insufficient to reject the proposed architecture.

The corrected operator packs those exact legal tokens and original positions as
shared query/key rows. Shared rows NEVER read pending drafts; private D rows
respect group ordering; I/O rows never become keys. Each original position still
has exactly one selected base/private version. All32 layers and this extra work
are paid. Public cache is immutable and no private KV is published.

Old records are preserved at `firebreak_preflight_20261003_9a35b9ce`.
Audited records are at `firebreak_context_audit_20261003_2362a929`, beneath the
server tuning run `tuning_gpu1_20260930_145350`.

| Two isolated groups | 11 | 21.312 | 2.915 |

| Four groups + cross veto | 8 | 22.642 | 5.971 |

The complete four-group operator accepts12 before its cross veto and8 after it,
also when pre/post veto are compared within the same query shape. One MBPP
candidate fails both cross argmax and JS; an early MATH JS veto also removes its
dependent local tail. Grouping has a small legal-progress signal, but the complete
operator does not yet benefit on these states.

Including the observed proposal, snapshot, metadata, stable verifier and gate,
matched instrumented work is1.075175s for the chain and1.100638s for the complete
operator. The shadow-progress-per-second ratio is0.78149. This ratio is NOT
online speedup: no FIREBREAK proposal was actually committed, no future cache
refresh policy has been benchmarked, and there is no saved NFE claim.

## Checks and limitations

* 20 CPU checks passed locally/server: version exclusivity, all-layer provenance,
prefix closure, shared isolation, JS and the pinned boundary mapping, plus WAVE.
* 12 real-model label perturbations produced zero forbidden ISO/O/shared/draft
change; public KV bit patterns were unchanged.
* Six32-layer dense-FP32 attention references agreed on the accepted sets with the
streaming implementation. Maximum full-logit error was0.25 and maximum candidate
probability error0.03140. This is decision agreement on selected states, NOT
bitwise equivalence or a guarantee near thresholds.
* Clean/observed ordinary Flash texts, actual commit traces and real model calls
matched for all six prompts. No Torch SDPA was called.
* The few accepted tokens matched the later ordinary Flash commits. That teacher
can itself be wrong; this is NOT gold accuracy or a losslessness claim.
